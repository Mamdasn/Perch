# Notchpop design

Settings uses compact native Calendars and General tabs without external links. The system places the navigation in the title bar where supported. “View Source on GitHub” lives in the menu-bar icon's menu and opens the Notchpop repository.

On notched displays, only the black notch triggers the 350 ms hover dwell. The visible screen below it and the adjacent menu bar do not trigger the card, leaving other apps' controls accessible. Once open, the card stays available while the pointer interacts with it; notchless displays retain their top-center trigger. Returning during dismissal grace keeps the card open without another dwell. After Settings opens, leaving the trigger clears hover suppression without requiring exit from the hidden card's former area.

Invitation cards show the current user's response as compact secondary text in the header: Accepted, Maybe, No response, or Delegated. Unknown responses and events organized by the user omit the label. Declined events remain excluded. The label is informational; responses are changed in Calendar.

General includes “Upcoming meeting highlight,” enabled by default and persisted with AppStorage. Turning it off immediately hides the pre-meeting reminder without changing hover feedback or popup behavior.

Connected users can choose “Disconnect Calendar” in General. This clears loaded events and persists an app-level disconnect across launches while retaining calendar selections and macOS permission. Calendars returns to the connection flow; reconnecting resumes event loading.

At the notch's upper corners, the highlight curves outward over 12 pt and tapers to zero width at the display edge. The halo follows the same contour, avoiding blunt endpoints.

When no meeting is in progress, the nearest upcoming meeting gets a reminder during its final five minutes: a 4 pt gradient stroke around the notch's sides and bottom, or a 72 × 2.5 pt line flush with the top edge on notchless displays. Horizontal placement uses the display's exact center relative to the overlay's actual frame; width and height use macOS's reported notch bounds. A symmetrical gradient blends system blue into system green as time advances, with a compact halo fading outward to transparency over 4 pt. A slow four-second pulse varies opacity between 80% and 100%. Reduce Motion keeps it steady; Increased Contrast uses a steady, opaque 5 pt notch stroke without glow. Reduce Transparency also removes the glow and makes the core gradient opaque before pulsing. The reminder disappears at the start time and ignores demo data. `MeetingReminder.swift` contains timing and rendering. The off-state hover preview compresses the color transition into five seconds, then blends back to blue over 0.6 seconds while hovered.

Settings uses a fixed 480 × 460 pt content area, preserving a compact, consistent layout. Both sections use native grouped forms and semantic system colors. Calendars contains scrollable checkbox rows and a refresh action, while disconnected users see a compact connection group with permission guidance. A single native “Load Demo Meeting” button sits beneath the form without a section or status copy. It opens a temporary sample immediately and keeps the same label. It waits up to eight seconds for the pointer; once entered, normal hover dismissal applies. Closing the preview restores calendar data. General groups startup, meeting highlights, and the calendar connection. Reopening the running app from Finder or the Dock brings Settings forward.

Launch at login is an opt-in setting backed by `SMAppService.mainApp` in `LoginSettings.swift`. It reflects macOS registration status, offers a System Settings link when approval is needed, and surfaces registration errors. No helper or LaunchAgent is required. Actual login after a restart remains a manual validation step.

SwiftUI handles content and native material; AppKit handles the nonactivating overlay and menu bar. The panel becomes key when the popup opens to receive arrow keys, and relinquishes key status when dismissed. Keyboard handling is local to the panel; modified arrow shortcuts pass through.

The idle overlay has no visible content. A 350 ms hover reveals a compact 336 × 286 pt meeting card with 18 pt padding and a two-line, 19 pt title; leaving dismisses it after a 250 ms grace period. Displays without a notch use the top center. Settings preview reveals the card automatically. The menu bar offers Settings, View Source on GitHub, and Quit. Launch does not open settings automatically.

Location and invited participant count share one secondary row; rooms and equipment are excluded from the count. Missing details and unavailable organizers leave no placeholders. A native Notes disclosure expands the card to 394 pt, with a bounded, selectable, scrolling description. Notes collapse when changing events or closing the card. Scrolling within notes reads the description instead of paging events; while expanded, arrow keys are left to the native controls and the previous/next buttons remain available. Disclosure motion respects Reduce Motion.

The surface uses dark native material, a subtle one-point border, system typography, and green to indicate an ongoing event. The icon is a shared original vector mark rendered as a template menu icon and a full-resolution macOS app icon.

The current meeting takes priority, otherwise the next meeting is featured. Scroll up or press Up for later events; scroll down or press Down for earlier ones. Chevron buttons use the same navigation handler and boundaries, with no wrapping. Event changes use a short vertical slide and fade; scroll momentum is ignored. Clicking an event title opens its Calendar event; Join opens its conference link.

The popup rolls down from the display's top edge in 320 ms, settles 18 pt below the notch, and retreats above the display on dismissal. Clipping applies at the screen edge rather than below the notch. A delicate hover outline grows from 2.5% to 8% opacity. A single centered Bézier bridge stretches toward the card, thins, and fades. A ring made from two rounded rectangles expands upward with the lag between card and fluid progress, then settles over 480 ms. This is a simple visual approximation, without particles or sampled perimeter waves. Card and fluid timing are independent.

The card and blur surface are prepared offscreen during the hover dwell, keeping their identity when rollout begins. The prepared card is excluded from interaction and accessibility until open. Steady hover does not republish unchanged progress values or repeatedly change the panel's mouse-event handling.

The trail uses 9% opacity before fading, the rim 8%, and its soft shadow 2%. These are layer opacities, not final composited pixel measurements. Reduce Motion removes the trail and uses a settled rim and brief fades. Reduce Transparency uses an opaque system background and disables fluid blur and glow. Increased contrast strengthens the base border. Decorative layers ignore pointer input and are hidden from accessibility.

Files under `Sources/Notchpop`: `main.swift` (overlay, focus, and settings), `Meetings.swift` (Calendar data and content), `MeetingPager.swift` (shared scrolling and keyboard navigation), `LiquidHighlight.swift` (bridge and rim), and `BrandIcon.swift` (identity). `scripts/RenderIcon.swift` renders icon assets; `scripts/InspectTrail.swift` previews trail geometry. Build with `bash build-app.sh`; check behavior with `.build/release/Notchpop --self-test`.

Calendar exclusions persist in UserDefaults. Calendar permission is managed by macOS and read at launch; it is not an app-owned connection flag. The default ad-hoc signature is tied to the executable's hash, so rebuilt installations can require fresh permission. `SIGNING_IDENTITY` allows builds to use a consistent installed signing certificate. See [Apple's signing requirements](https://developer.apple.com/documentation/technotes/tn3127-inside-code-signing-requirements).

The 22 automated checks cover hover state, event selection, links, and navigation boundaries. They do not verify rendered animation or keyboard focus delivery. Remaining manual validation: VoiceOver, keyboard interaction and focus restoration, full-screen Spaces, multiple displays, accessibility display settings, and account-specific Calendar behavior.
